# TVBox 自建源 · 自动构建与存活探测

一套自动运行的 TVBox 源服务：把散落的源 JSON **集中合并去重**，定时自动**探测存活、剔除失效源**，并推送到你的仓库，电视/手机直接填仓库地址即可。**不需要 nginx、域名或 HTTPS。**

- 纯 Python 标准库，**零第三方依赖**
- 源文件**只读**：失效只影响当次输出，恢复后自动放回，永不删源
- 部署到服务器后 cron/systemd 定时跑，无需人工干预

## 核心能力

| 能力 | 说明 |
|------|------|
| 多源合并 + 本质去重 | sites 按 `type+api+ext+jar+url` 本质签名去重（非按 key），去换皮、保实质不同的实现；内容完全相同的源配置提前去重 |
| rules 按 host 并集合并 | 同 host 的规则合并为一条，`regex/rule/filter/script` 各字段取并集，找回被"首个胜出"丢弃的独有规则 |
| 存活探测 + 测速排序 | 并发探测每个源，sites/parses 按 API 响应时间 `_rt` 排序，直播额外测 m3u8 分片下载速度 `_prt` |
| deep 内容验证 | type 0/1 站点读响应体，识别"返回 200 但内容无效"（空 list / 错误页 / 登录页） |
| 失败黑名单 | 连续失败达阈值（默认 5 次）自动拉黑跳过，探测/拉取两类独立计数，可手动/批量释放；探测可靠性三件套：熔断（网络异常不写黑名单）+ conn_error 半超时重试（抖动不判死）+ 自动重试探（页面显示倒计时，可一键全部放出） |
| 健康分级 ⚠ 标记 | 近期连续失败又恢复的"时好时坏"源，name 加 `[⚠]`，直观可见，不用等拉黑才发现 |
| 手动禁用 | 页面搜索产物中的源，一键禁用（如广告源），构建时跳过，可恢复 |
| Spider JAR 全链路处理 | 投票统计 → per-site jar 兜底 → 可达性探测 → 死链 jar 自动救治 → jar 类名审计 |
| 站点 diff | 与上次构建对比，输出新增/移除站点 |
| 容错解析 | 容忍 BOM、JS 注释、尾逗号、控制字符、缺引号、UTF-8/GB18030 编码；整份坏掉按条"抢救" |
| 站点名推广文字清洗 | 外科手术式清除 URL/联系方式/推广关键词/更新日期章，不动表情、竖线、技术标记等命名风格 |
| 远程源拉取 | 从 `dc.txt` 并发抓取远程源缓存到 `fetched/`，断网回退上次缓存；连续失败达阈值的条目输出"建议从 `dc.txt` 移除"清单 |
| 安全阀 | 存活数低于阈值时拒绝覆盖，防断网把好源清空 |
| 企业微信通知 | 构建成功推结果摘要，安全阀触发/构建崩溃推告警；管理页直接看绑定状态 + 一键发测试消息 |
| 管理后台 | 零依赖 Web 页面：上传/抓取/粘贴新源、一键构建（实时进度+耗时）、黑名单管理（倒计时 + 一键放出）、源搜索禁用、通知绑定状态 |
| 离线回归测试 | `tests/` 27 例单测，一条命令跑完，不联网；改核心逻辑前先跑，防止夜间构建被改崩 |

## 快速开始

```bash
python3 build.py                 # 完整构建（拉远程源 + 探测 + 测速 + 去重 + 输出）
python3 build.py --no-probe      # 只合并不探测（离线/调试）
python3 manage.py                # 管理后台 0.0.0.0:8787
python3 build.py --notify-capture   # 绑定企业微信通知（首次使用，见下文）
python3 tests/run_all.py         # 离线回归测试（27 例，秒级，不联网）
```

## 工作原理

```
sources/*.json + dc.txt 远程源
      │  容错解析(BOM/注释/尾逗号/GBK 混编/逐条抢救)
      ▼
配置级去重 ──► 合并(标量取首个非空 / URL 字段收集候选 / 字符串列表并集)
      │        └─ rules 按 host 并集合并 ── 字典列表按本质签名去重
      ▼
手动禁用清单剔除 ──► 站点名推广文字清洗(URL/联系方式/推广关键词/更新日期章)
      │
      ▼
静态字段清洗(wallpaper/logo/spider/danmaku, 排除内网地址+探测)
      │
      ▼
JAR 处理：投票统计 ──► per-site jar 兜底 ──► 可达性探测 ──► 死链救治 ──► 类名审计
      │
      ▼
站点 diff(与上次构建的快照对比, 输出新增/移除)
      │
      ▼
存活探测(并发) + deep 内容验证 + 测速──► conn_error 半超时重试 ×1
      │        ──► 黑名单计数 / 熔断 / 健康分级 ⚠ 标记 / 自动重试探
      │
      ▼
安全阀(存活数 < max(min-sites, 上次存活×min-ratio) 则拒绝覆盖)
      │
      ▼
产物输出 ──► 企业微信通知(成功推结果 / 失败推告警)
```

各类源的探测方式：

- **type 1/0（CMS 接口）**：`api` 是接口 URL，直接探测 + deep 内容验证，最可靠
- **type 3（爬虫）**：`api` 为远程 `.js/.py` 可探测；为 `csp_XXX` 依赖 App 内置爬虫 → 保留为"客户端依赖"（服务器无法探测，故另有 lite 产物）
- **直播/解析**：直接探测 `url`；直播额外测 m3u8 分片下载速度

## 功能说明

### 1. 多源合并与去重

- **本质去重**（sites）：去重键为 `(type, api, ext, jar, url)` 组合签名
  - 去掉换皮：同一 `api+ext` 不同 `key/name` 的源只保留首个（如"多多|4K"重复 4 个 → 留 1 个）
  - 找回误杀：`key` 相同但 `api/ext` 不同的源都保留（如"圣城影视"有 Java 爬虫和 JS 脚本两种实现，旧逻辑只留 1 个）
- **配置级去重**：内容完全相同（忽略条目顺序与内部标记）的源配置只保留第一个，本地源优先于 `fetched/` 缓存
- **rules 合并**：host 集合相同的规则折叠为一条，`regex/rule/filter/script` 取并集，`name` 等标量保留首条非空；无 host 的匿名规则原样保留；始终复制列表再追加，不污染源配置

### 2. 存活探测与测速排序

构建时对每个存活源记录响应时间，产物里带 `_rt` 字段（客户端会忽略）：

- **点播源（sites）**：按 API 响应时间 `_rt` 排序，快的排前面
- **直播源（lives）**：额外测 m3u8 第一个 ts 分片下载 64KB 耗时 `_prt`，按播放速度排序
- **解析源（parses）**：按 API 响应时间 `_rt` 排序（客户端按顺序尝试解析，快的在前少等待）
- 测速失败的源排到末尾，不影响使用

### 3. deep 内容验证

浅层探测只能判断"HTTP 200 且有字节返回"，识别不了**返回 200 但内容无效**的源（空 list、系统维护页、登录页）。deep 验证对 type 0/1 CMS 站点多读一步响应体（上限 128KB）：

- type 1（JSON）：`list`/`class` 任一为非空数组 → 有效；两者皆空/缺失 → 判失效
- type 0（XML）：含 `<list>`/`<video>`/`<class>` 标签 → 有效
- **宽进严出**：JSON 被 128KB 截断时按 `"list"` 引号标记兜底判有效；拿不准的一律按有效，不会误杀
- 验证失败判失效（`invalid_content`），不重试；`--no-deep-check` 可关闭

### 4. 健康分级 ⚠ 标记

黑名单是二值状态（正常/拉黑），中间没有过渡。**健康分级**补上这一档：

- 站点本次探测**恢复了**，但此前已连续失败 3~4 次（未达拉黑阈值）→ 输出时 name 追加 `[⚠]`
- 主源/稳妥源/审计源/注释版都能看到，客户端会忽略该后缀
- `report.md` 有"不稳定源"小节列出连续失败次数；管理页状态行显示 ⚠ 计数
- 阈值可调：`--warn-threshold N`（默认 3，0 关闭）；值 ≥ `--fail-threshold` 时自动关闭

### 5. 失败黑名单与手动禁用

| 机制 | 文件 | 触发 | 作用 |
|------|------|------|------|
| 失败黑名单 | `probe_blacklist.json` | 连续失败 ≥5 次自动拉黑 | 跳过探测/拉取，可手动释放 |
| 手动禁用 | `disable_list.json` | 页面搜索后点「禁用」 | 构建时移除，下次不出现，可恢复 |

两者都会让构建跳过对应源，区别：黑名单是自动累积失败（探测成功清零，可恢复），禁用是人工主动剔除（如广告源）。黑名单还会自动清理"URL 已不在本轮配置中"的僵尸记录，防止文件无限膨胀、防止源回归时被陈旧记录判死。

**熔断（防坏构建污染）**：一次断网/限速的构建会把几百个源推到阈值**永久拉黑**（真实发生过：2026-10-14 上午一次只有 416 存活的异常构建，把 465 个源判了死）。因此本轮探测中连接级失败（conn_error）占比 ≥ `--blacklist-breaker`（默认 0.6）且探测数 ≥ `--breaker-min-probes`（默认 30）时，判定本轮网络异常，**放弃本轮黑名单写入**（恢复探测前的计数）并推送企业微信告警。产物仍按本轮探测输出，由安全阀兜底。

**自动重试探（防永久误杀）**：已达阈值的条目距 `last_fail` 超过 `--blacklist-retry-days`（默认 7 天）后，本轮自动放出来重新探测——活了清零复活（进"本次恢复的源"），死了重新计时。误杀最多冻结 7 天而非永久。置 0 关闭。

**conn_error 半超时重试**：连接级失败（DNS/超时/连接被重置）先用原超时试一次，失败再以**半超时**（`max(2, timeout//2)`）重试 1 次才判失败。网络抖动不再轻易把源推进黑名单；HTTP 状态码错误与 deep 内容无效属确定性失败，不重试。

**不用干等 7 天**：管理页黑名单列表带「自动重探」列显示"距自动重探 N 天"（`retry_in_days`），并提供**「一键全部放出」**批量释放全部条目（源存活 + 远程拉取），下次构建立即重新探测。`retry_days` 随黑名单文件落盘（`probe_blacklist.json`），页面与构建用的是同一个值。

### 6. 远程源拉取

默认从 `dc.txt`（远程源地址清单）并发抓取，缓存到 `fetched/`：

- 抓取**成功**才更新缓存；**失败但已有缓存** → 保留上一份（断网也不丢源）
- 远程源同样经过容错解析、合并去重、存活探测，和本地源一视同仁
- 拉取失败也计入黑名单（`fetch_entries`，与探测独立计数）
- `--no-fetch` 只用已有缓存；`--fetch-list` 可换清单文件

**远程源健康清单**：连续拉取失败已达阈值的条目（后续构建不再抓取、只用越来越旧的缓存）会被汇总成"建议从 `dc.txt` 移除"清单，写进 `report.md` / `report.json` 的 `fetch_dead`，管理页「监测报告 → 远程源健康」同样展示。清 `dc.txt` 有据可依，不再靠猜。

### 7. Spider JAR 处理

多源合并时不同源带不同 `spider` JAR，type:3 站点依赖 JAR 运行。本项目做了一整条链路：

| 步骤 | 作用 |
|------|------|
| 投票统计 | 统计各源 spider 被多少 type:3 站点引用，只观测不改行为 |
| per-site jar 兜底 | 非全局 JAR 的 type:3 站点单独设 `jar` 字段；相对路径 spider 按来源 URL 解析为绝对 URL，顺带救治源声明的相对路径死链 |
| 可达性探测 | 对产物引用的全部 jar URL 并发探测，输出可达/失效与受影响站点数 |
| 死链 jar 自动救治 | jar 已失效的站点，若全局 spider 的 jar 里**已验证存在**对应爬虫类（下载 jar → 解 DEX 字符串池 → 类名匹配），则摘除该站点 jar 改走全局 spider；无法验证则不动 |
| jar 类名审计 | 抓"地址活着但 jar 里没有对应爬虫类"的静默故障站点；结论按 jar 全值缓存（内容寻址），只有新 jar 才下载解包 |

### 8. 静态字段清洗

为 `wallpaper`/`logo`/`homeLogo`/`danmaku`/`spider` 等顶层字段挑选真正可用的地址：排除本机/内网地址 → 并发探测连通性 → 取首个可用的；都不可用则置空（spider 例外，挑不到就保留第一个非本机候选）。

### 9. 站点 diff

每次构建与上次的站点快照（`.site_snapshot.json`，已 gitignore）对比，输出新增/移除站点数量与样本。身份标识优先 `key`，其次 `api+name`，**刻意不含 jar/ext**（这两字段会被清洗与兜底改写，含了会产生虚假 diff）。

### 10. 安全阀

防止服务器断网/大范围异常时把好源覆盖成空的：存活站点数低于 `max(--min-sites=20, 上次存活数 × --min-ratio=0.5)` 时拒绝覆盖产物、返回非 0，并推送企业微信告警。线上文件保持上一次的有效源。

### 11. 容错解析

上游源文件经常损坏，实测踩到的坑都做了处理：BOM、JS 注释、尾逗号、字符串内裸控制字符、缺引号、多余引号、UTF-8/GB18030 编码混编。整份解析仍失败时，按花括号配平**逐条抢救** sites/lives/parses，好的留下、坏的跳过。

### 12. 站点名推广文字清洗

**为什么不做"激进清洗"**：对 4727 个真实站点名做过统计——95%+ 是合法命名风格，激进的括号/表情/分隔符清洗会把名字改得面目全非：

| 长这样的 | 是什么 | 处理 |
|----------|--------|------|
| `❤玩偶｜4K`、`🔥豆瓣┃推荐`、`💥玩偶┃4K` | 源的品牌风格（表情+竖线） | **不动** |
| `xxx[js]`、`xxx[jar]`、`xxx[py]`、`鹅块[优]` | 技术标记/分类标记 | **不动** |
| `📺️腾讯 \| 官方`、`官方采集M` | 官方线路描述 | **不动** |
| `TG群组搜索` | 真名（不是广告） | **不动** |

只删四类**高置信度推广残留**（每条模式都带关键字门禁或结构特征，不会误伤上面那些）：

1. **URL/域名残留**：`导航 http://bhapp.top/` → `导航`；`某某影视 xyz.com` → `某某影视`
2. **联系方式**（必须带冒号/数字/ @ 等结构特征）：`xx QQ群:1111119113` → `xx`；`xx 微信:abc` → `xx`
3. **推广关键词短语**：永久域名、官网地址、最新网址、发布地址、防迷路、收藏本站、注册送、招代理等
4. **更新日期章**：`玩偶❤更新10-05` → `玩偶`；`xx 更新至10.05` → `xx`

安全设计：

- 删完收拾首尾分隔符；**清洗后为空则保留原名**（宁可不洗也别没名字）
- **幂等**（重复清洗无变化），全量实测 4727 → 仅 2 个命中、零误伤
- 必须在站点 diff **之前**执行（清洗确定性 → `api+name` 身份跨构建稳定）；实测受影响的无 key 站点 0 个，diff 零抖动
- `--no-clean-names` 可关闭

## 企业微信通知

构建结果推送到企业微信智能机器人（长连接 API 模式，零依赖自实现 WS 客户端）：

| 时机 | 内容 |
|------|------|
| 构建成功 | 耗时、点播/直播/解析存活失效数、恢复/新失效、站点增删、产物数量 |
| 安全阀触发 | 存活数 vs 阈值，提示线上仍是上次有效源 |
| 构建崩溃 | traceback 末尾 |

**首次使用必须绑定会话**（机器人只能向"你已发过消息"的会话主动推送，这是协议要求）：

```bash
python3 build.py --notify-capture   # 运行后，去企业微信给机器人发任意消息
python3 build.py --notify-test      # 发一条测试消息验证绑定
```

绑定信息（chatid）存 `notify_config.json`；`--no-notify` 可整体关闭。凭证在 `tvbox_core/notify.py` 顶部默认值，可用 `notify_config.json` 的 `bot_id`/`secret` 覆盖，`enabled: false` 关闭。

管理页「总览 → 企业微信通知」直接显示绑定状态（已绑定会显示 chatid 与单聊/群聊，未绑定会提示去服务器跑 `--notify-capture`），并提供**「发送测试消息」**按钮，不用再靠盲猜绑没绑。

## 管理后台

`python3 manage.py` 启动后浏览器打开 `http://IP:8787`：

| 卡片 | 能力 |
|------|------|
| **状态** | 实时构建进度条（5 阶段）、构建耗时、⚠ 不稳定计数、一键重新构建/推送 |
| **方式一：上传 JSON 文件** | 选择 `.json` 上传保存（同名自动备份到 `sources_backup/`） |
| **方式二：用远程 URL 抓取** | 填源地址，服务端抓取保存 |
| **方式三：直接粘贴内容** | 复制粘贴 JSON 文本保存 |
| **当前源文件** | 列出 `sources/` 所有文件，显示黑名单关联数 + 取消拉黑 |
| **失败黑名单** | 合并表格（源存活/远程拉取），搜索+分页，手动释放；带「自动重探」倒计时列 + 一键全部放出 |
| **不稳定源 ⚠** | "时好时坏"的源明细（近期连败后恢复，产物 name 带 `[⚠]`） |
| **deep 失效源** | 返回 200 但内容无效的源明细（空 list / 错误页 / 登录页） |
| **源文件贡献度** | 每个源文件贡献多少存活/失效/拉黑站点（失效最多在前，供清理决策） |
| **远程源健康** | `dc.txt` 里已达拉取阈值的远程源（建议从 `dc.txt` 移除） |
| **企业微信通知** | 绑定状态（chatid/单聊群聊）+「发送测试消息」按钮 |
| **源搜索与禁用** | 按 name/api/ext 搜索产物中的源，一键禁用（持久化，构建跳过），可恢复 |
| **构建日志** | 实时流式输出 |

保存时校验合法性（不含 `sites`/`lives`/`parses` 会被拒）。网页触发的构建与 cron 共用同一把 `flock` 锁，不会并发冲突。

> **改了 `tvbox_core/` 代码后必须重启 `manage.py`**：页面与 API 都在进程内存里，旧进程 serve 旧页面（2026-10-14 因此产生过"改了没生效"的误判）。页脚有"页面版本"（页面文件 mtime），用它核对当前看到的是不是最新页面。
>
> 顶部 Tab 支持深链接：`http://IP:8787/#monitor`、`#manage`、`#add`，可直接把某个 Tab 的地址收藏/分享。

## 常用参数

```bash
# 探测
python3 build.py --workers 128 --timeout 4        # 默认: 高并发短超时
python3 build.py --no-deep-check                  # 关闭 deep 内容验证
python3 build.py --no-clean-names                 # 关闭站点名推广文字清洗
# 远程拉取
python3 build.py --fetch-workers 128 --fetch-timeout 4
python3 build.py --no-fetch                       # 只用 fetched/ 已有缓存
python3 build.py --fetch-list dc.txt              # 换远程源清单文件
# 阈值
python3 build.py --fail-threshold 5               # 黑名单阈值(连续失败次数)
python3 build.py --warn-threshold 3               # 健康分级阈值(⚠ 标记, 0 关闭)
python3 build.py --blacklist-breaker 0.6          # 熔断: 连接失败占比阈值(0 关闭)
python3 build.py --breaker-min-probes 30          # 熔断: 最小探测数(防小样本误触)
python3 build.py --blacklist-retry-days 7         # 黑名单自动重试探天数(0 关闭)
python3 build.py --no-blacklist                   # 关闭黑名单机制
python3 build.py --min-sites 20 --min-ratio 0.5   # 安全阀阈值
# 通知
python3 build.py --no-notify                      # 关闭企业微信通知
python3 build.py --notify-capture                 # 绑定通知会话(首次使用)
python3 build.py --notify-test                    # 发送测试消息
# 其他
python3 build.py --no-probe                       # 只合并不探测(离线/调试)
python3 build.py --out www --src sources          # 产物目录 / 源目录
```

## 回归测试

核心逻辑（探测判定/黑名单/合并/通知协议）全部有离线单测，一条命令跑完，**改任何核心逻辑前先跑一遍**，防止夜间构建被改崩：

```bash
python3 tests/run_all.py            # 或 python3 -m unittest discover -s tests -v
```

不访问网络（探测与拉取均 mock），秒级完成。覆盖：

| 测试文件 | 覆盖内容 |
|---|---|
| `tests/test_probe_deep.py` | deep 内容验证（空 list / 截断 / XML / 错误页） |
| `tests/test_probe_health.py` | 健康标记 ⚠、黑名单计数与拉黑、熔断回滚、自动重试探、conn_error 半超时重试、倒计时计算 |

| `tests/test_output_report.py` | 报告里的远程源健康清单（json + md） |

## 关键设计

- **源只读，失效可逆**：源文件永不改动，失效只影响当次输出，下次探测到恢复自动放回
- **本质去重**：按 `api+ext` 去换皮、按 `key` 误杀找回，产物源数更准确
- **rules 并集合并**：按 host 折叠而非"首个胜出"去重，规则覆盖不减
- **宽进严出的 deep 验证**：只对"确定无效"判失效，不误杀
- **测速排序**：慢源自动靠后，改善"打开转半天"体验
- **禁缓存**：HTTP `no-store` + JSON 内 `updated` 字段，双层保证拉到最新
- **安全阀 + 异常告警**：拒绝覆盖的同时推送企业微信，无人值守也有感知
- **探测可靠性三件套**：熔断（坏网络不写黑名单）+ conn_error 半超时重试（抖动不判死）+ 自动重试探（误杀 7 天解封，页面可提前批量放出）
- **离线回归测试**：`tests/` 一条命令跑完，改核心逻辑前先跑
- **防重入**：`deploy/update.sh` 用 `flock` 锁，构建后自检 JSON，不通过不动线上文件
